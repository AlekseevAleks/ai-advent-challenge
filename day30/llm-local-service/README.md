# Локальный приватный LLM-сервис

Учебный HTTP-сервис на Python, который передаёт чат локально установленной модели через Ollama. FastAPI выполняет проверку входных данных, rate limit и контроль размера контекста; пользовательские сообщения не отправляются в OpenAI, Anthropic или другие внешние AI-сервисы.

> **Модель и железо.** В примерах используется `llama3.2:3b` (квантованный вариант около 2 ГБ). Это компактная модель, но её запуск не гарантируется на любом компьютере: необходимы подходящие оперативная память, процессор/GPU и свободное место. До запуска проверьте системные требования Ollama, свободную память и дисковое пространство. Если модель работает медленно или не помещается в память, попробуйте меньшую совместимую модель (например, `llama3.2:1b`) и укажите её точное имя в `OLLAMA_MODEL`. Более крупные модели, например 7B, обычно требуют больше ресурсов.

## 1. Описание проекта

Сервис предоставляет HTTP API поверх локальной LLM. Ollama запускает модель на этом же компьютере, а FastAPI принимает и валидирует запросы, ограничивает частоту и размер контекста, затем передаёт историю локальному серверу Ollama. По умолчанию API слушает только `127.0.0.1`; Ollama используется по `127.0.0.1:11434` и не должна быть доступна из домашней сети или интернета.

История диалога не хранится как состояние разговора в API: для многошагового общения клиент каждый раз передаёт все предыдущие сообщения. Отдельно, по умолчанию включён подробный журнал `REQUEST_LOG_ENABLED`, который сохраняет копии полных сообщений и ответов в локальные JSON-файлы. Его можно выключить на странице настроек; детали описаны ниже.

## 2. Возможности

- `GET /health/live` — liveness-проверка, не обращается к модели.
- `GET /health` — проверка API, Ollama и наличия выбранной модели; при сбое возвращает HTTP 503 за ограниченное время.
- `POST /chat` — асинхронная генерация через локальный Ollama `/api/chat`.
- **OpenAI-compatible API для AI-агентов:** `GET /v1/models`, `POST /v1/chat/completions` (включая `stream=true` как настоящий SSE), `temperature`, `max_tokens`; подключение через официальный OpenAI SDK с `base_url=http://127.0.0.1:5012/v1` и `model=local-llm`.
- Отдельные ключи: `API_KEY` для панели и `OPENAI_API_KEY` для `/v1/*`.
- `GET /docs` — автоматическая Swagger UI; `GET /openapi.json` — схема API.
- Роли сообщений `system`, `user`, `assistant`; последним сообщением должен быть `user`.
- Rate limit по IP клиента, настраиваемый через `RATE_LIMIT` (по умолчанию 10/мин).
- Ограничение длины сообщения, числа сообщений, контекста и количества генерируемых токенов.
- Таймауты, обработка недоступной Ollama/отсутствующей модели и единый безопасный JSON-формат ошибок.
- Необязательная веб-панель на `/`: обзор статуса, настройка модели на лету, выбор установленной модели, журнал с поиском/фильтрацией и просмотром диалогов.
- Необязательная аутентификация через API key защищает `/chat` и административные API; ключ вводится в панели только в память текущей вкладки.
- JSON-журнал запросов с полными текстами, ограничением хранения и явной кнопкой очистки; запись можно выключить.
- Нагрузочный скрипт: последовательные либо ограниченно параллельные реальные вызовы `/chat`.
- Автотесты не скачивают модель и не делают внешних AI-запросов.

## 3. Архитектура

```text
HTTP-клиент (curl / приложение)
             |
             v
      FastAPI (127.0.0.1:5012)
             |
     Pydantic-валидация
             |
     API key (опционально)
             |
       Rate limit по IP
             |
     Проверка размера контекста
             |
     HTTPX AsyncClient
             |
             v
 Ollama API (127.0.0.1:11434)
             |
             v
     Локальная модель
```

API и Ollama — два разных локальных процесса. Не настраивайте Ollama на публичный интерфейс и не публикуйте порт `11434`.

## 5. Требования к оборудованию

- Python 3.11+ (проект проверяется на Python 3.12).
- Ollama для вашей ОС.
- Место на диске для файла модели и оперативная память для модели и её контекста.
- Для `llama3.2:3b` скачиваемый артефакт в этом окружении — около 2 ГБ; фактическая память при работе зависит от Ollama, размера контекста и платформы.
- CPU-only запуск возможен, но генерация может быть медленной. GPU не обязателен для API, но может ускорить модель, если поддерживается Ollama.

Перед загрузкой модели проверьте память/диск средствами своей ОС. Примеры быстрой проверки:

```bash
# macOS
system_profiler SPHardwareDataType
 df -h .

# Linux
free -h
 df -h .
```

В Windows PowerShell:

```powershell
Get-CimInstance Win32_ComputerSystem | Select-Object TotalPhysicalMemory
Get-PSDrive -Name C
```

Также проверьте, что Ollama поддерживает выбранное устройство/ускоритель, и уточните актуальные требования на официальном сайте Ollama и странице модели. Не считайте 3B-модель гарантированно совместимой со всеми компьютерами. Если модель не запускается, выберите меньшую модель, уменьшите `OLLAMA_NUM_CTX` вместе с лимитами контекста и проверьте логи Ollama.

## 6. Установка Python

### macOS

Установите Python 3.11+ с [python.org](https://www.python.org/downloads/macos/) или через Homebrew:

```bash
brew install python@3.12
python3.12 --version
```

### Windows

Установите Python 3.11+ с [python.org](https://www.python.org/downloads/windows/), отметьте **Add python.exe to PATH**, затем в PowerShell:

```powershell
py -3.12 --version
```

### Linux (Ubuntu/Debian)

Используйте пакет Python 3.11+ вашей версии дистрибутива и `venv`:

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip
python3 --version
```

Если в дистрибутиве Python младше 3.11, установите совместимую версию штатным для вашей системы способом.

## 7. Установка Ollama

Установите Ollama только с официального сайта: <https://ollama.com/download>.

- **macOS:** загрузите приложение Ollama и запустите его; сервер обычно стартует вместе с приложением.
- **Windows:** запустите официальный установщик Ollama и проверьте, что приложение/служба запущена.
- **Linux:** следуйте инструкции установки на официальном сайте Ollama. После установки сервер обычно запускается как системная служба; при ручном запуске используйте `ollama serve`.

Проверка версии и локального API:

```bash
ollama --version
curl http://127.0.0.1:11434/api/tags
```

Если `curl` не получает JSON, убедитесь, что Ollama запущена. API Ollama должен оставаться локальным.

## 8. Загрузка выбранной модели

```bash
ollama pull llama3.2:3b
ollama list
```

Загрузка выполняется отдельно от старта FastAPI; сервер **не скачивает** модель автоматически при запуске. `llama3.2:3b` приводится как пример компактной модели. В зависимости от оборудования можно выбрать, например, `llama3.2:1b` или другую совместимую модель, но измените `OLLAMA_MODEL` на точное имя из `ollama list` и прочитайте её лицензию.

## 11. Настройка `.env`

Скопируйте шаблон:

### macOS / Linux

```bash
cp .env.example .env
```

### Windows PowerShell

```powershell
Copy-Item .env.example .env
```

Основные параметры:

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `HOST` | `127.0.0.1` | Адрес API; localhost-only по умолчанию |
| `PORT` | `5012` | Порт API |
| `API_KEY` | пусто | Необязательный ключ; защищает `/chat` и `/api/admin/*`, если задан |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | Локальный HTTP API Ollama |
| `ALLOW_REMOTE_OLLAMA` | `false` | Явное подтверждение доверенному Ollama-узлу в собственной LAN; публичный endpoint использовать нельзя |
| `OLLAMA_MODEL` | `llama3.2:3b` | Имя уже загруженной модели |
| `OLLAMA_TIMEOUT` | `120` | Общий timeout генерации, секунды |
| `OLLAMA_CONNECT_TIMEOUT` | `5` | Timeout подключения |
| `OLLAMA_NUM_CTX` | `4608` | Размер контекстного окна, переданный Ollama |
| `OLLAMA_MAX_CONCURRENCY` | `1` | Максимум одновременных запросов к модели; `1` ставит генерации в очередь |
| `RATE_LIMIT` | `10/minute` | Лимит на IP; допустимые периоды: `second`, `minute`, `hour`, `day` |
| `MAX_MESSAGE_CHARS` | `4000` | Максимум символов в одном сообщении |
| `MAX_HISTORY_MESSAGES` | `20` | Максимум сообщений на запрос, включая system и новое сообщение |
| `MAX_CONTEXT_TOKENS` | `4096` | Максимум входного контекста до резерва на погрешность |
| `MAX_OUTPUT_TOKENS` | `512` | Максимум токенов генерации (`num_predict`) |
| `CONTEXT_TOKEN_TOLERANCE` | `0.05` | Доля входного бюджета, отведённая на погрешность оценки токенов |
| `TOKENIZER` | `heuristic` | Эвристическая оценка; `tiktoken` — необязательная приблизительная альтернатива |
| `TRUST_PROXY_HEADERS` | `false` | По умолчанию `X-Forwarded-For` не доверяется |
| `REQUEST_LOG_ENABLED` | `true` | Сохранять полные сообщения и ответы модели на диск |
| `REQUEST_LOG_DIR` | `logs/requests` | Каталог JSON-журналов; исключён из Git |
| `REQUEST_LOG_MAX_ENTRIES` | `500` | Максимум файлов; старейшие автоматически удаляются |

Параметры проверяются при запуске. Должно выполняться:

```text
MAX_CONTEXT_TOKENS + MAX_OUTPUT_TOKENS <= OLLAMA_NUM_CTX
```

Входной запрос должен помещаться в `MAX_CONTEXT_TOKENS` с учётом резерва на оценку. Значение контекста модели и допустимая скорость зависят от оборудования. `num_ctx` в Ollama не заменяет входные проверки FastAPI.

## 12. Запуск API

Из корня проекта:

```bash
python scripts/run_server.py
```

Этот скрипт читает `HOST`/`PORT` из `.env` и запускает Uvicorn. По умолчанию сервер слушает только `127.0.0.1:5012`. В Windows PowerShell используется та же команда:

```powershell
python scripts/run_server.py
```

Для ручного запуска с адресом/портом, явно заданными в команде:

```bash
uvicorn app.main:app --host 127.0.0.1 --port 5012
```

При LAN-конфигурации запускайте `python scripts/run_server.py`, чтобы Uvicorn прочитал заданный `HOST=0.0.0.0`; перед этим настройте `API_KEY` и firewall (см. раздел 24). Не используйте `--reload` при нагрузочном тестировании.

Остановка — `Ctrl+C`. Uvicorn закрывает HTTPX-пул соединений при остановке приложения.


## 13. Проверка доступности сервиса

В другом терминале на macOS/Linux:

```bash
curl -i http://127.0.0.1:5012/health/live
curl -i http://127.0.0.1:5012/health
```

Windows PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:5012/health/live
Invoke-RestMethod http://127.0.0.1:5012/health
```

- `GET /health/live` возвращает `200`, если работает процесс FastAPI, даже при выключенной Ollama.
- `GET /health` возвращает `200`, если Ollama доступна и модель установлена; иначе `503` и понятный статус `unavailable`/`model_missing`.
- Проверка Ollama имеет короткий timeout и не должна зависать.

## 14. Пример запроса через curl

```bash
curl -i http://127.0.0.1:5012/chat \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"Привет! Расскажи, что ты умеешь."}]}'
```

PowerShell:

```powershell
$body = @{ messages = @(@{ role = 'user'; content = 'Привет! Расскажи, что ты умеешь.' }) } | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5012/chat -ContentType 'application/json' -Body $body
```

Формат успешного ответа:

```json
{
  "response": "Ответ, сгенерированный установленной локальной моделью.",
  "model": "llama3.2:3b",
  "done": true
}
```

Содержимое ответа зависит от модели и запроса. Частые ошибки:

- `422` — некорректный JSON, роль, пустое сообщение или последнее сообщение не `user`;
- `413` — превышена длина сообщения, число сообщений или оценка контекста;
- `429` — превышен rate limit, ответ содержит `Retry-After`;
- `503` — Ollama недоступна или модель не установлена;
- `504` — истёк timeout генерации.

## 15. Пример многошагового чата

FastAPI не хранит состояние диалога. Для продолжения передавайте полную историю, включая ответы модели:

```bash
curl http://127.0.0.1:5012/chat \
  -H 'Content-Type: application/json' \
  -d '{"messages":[
    {"role":"system","content":"Отвечай по-русски кратко."},
    {"role":"user","content":"Запомни кодовое слово: кедр."}
  ]}'
```

Предположим, модель ответила «Запомнил: кедр». Следующий запрос включает историю:

```bash
curl http://127.0.0.1:5012/chat \
  -H 'Content-Type: application/json' \
  -d '{"messages":[
    {"role":"system","content":"Отвечай по-русски кратко."},
    {"role":"user","content":"Запомни кодовое слово: кедр."},
    {"role":"assistant","content":"Запомнил: кедр."},
    {"role":"user","content":"Какое кодовое слово я назвал?"}
  ]}'
```

Windows PowerShell:

```powershell
$messages = @(
  @{ role = 'system'; content = 'Отвечай по-русски кратко.' },
  @{ role = 'user'; content = 'Запомни кодовое слово: кедр.' },
  @{ role = 'assistant'; content = 'Запомнил: кедр.' },
  @{ role = 'user'; content = 'Какое кодовое слово я назвал?' }
)
$body = @{ messages = $messages } | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5012/chat -ContentType 'application/json' -Body $body
```

Клиент должен подставлять фактический предыдущий ответ модели. Последним должно быть сообщение `user`; `system`-инструкция может находиться только в начале истории.

## 16. Подключение AI-агента через OpenAI-compatible API

Сервис предоставляет минимально достаточное подмножество OpenAI Chat Completions API, чтобы агент подключался стандартными параметрами OpenAI SDK.

Параметры подключения:

| Параметр | Значение |
|---|---|
| `base_url` | `http://127.0.0.1:5012/v1` |
| `api_key` | значение `OPENAI_API_KEY` из `.env` (если пусто — `API_KEY`) |
| `model` | `local-llm` (алиас; также принимается реальное имя, например `llama3.2:3b`) |

### Шаг 1. Задайте ключ агента

```bash
# macOS / Linux
openssl rand -hex 24
```

Запишите результат в `.env` и перезапустите сервис:

```env
OPENAI_API_KEY=<случайная строка>
OPENAI_MODEL_ALIAS=local-llm
OPENAI_REQUIRE_API_KEY_FOR_MODELS=true
```

Если `OPENAI_API_KEY` пуст, маршруты `/v1/*` используют `API_KEY`. Если оба ключа пусты, аутентификация отключена — это допустимо только в loopback-режиме.

### Шаг 2. Проверьте HTTP-запросами

```bash
# список моделей
curl http://127.0.0.1:5012/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY"

# обычный ответ
curl http://127.0.0.1:5012/v1/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"local-llm","messages":[{"role":"user","content":"Привет!"}]}'

# потоковая генерация (SSE)
curl -N http://127.0.0.1:5012/v1/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"local-llm","stream":true,"messages":[{"role":"user","content":"Назови три цвета."}]}'
```

### Шаг 3. Подключите агента

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:5012/v1",   # локальный сервис, не облако
    api_key="<ваш OPENAI_API_KEY>",
    timeout=180.0,
)

# История передаётся целиком: сервер не хранит состояние диалога
messages = [{"role": "system", "content": "Отвечай кратко по-русски."}]
messages.append({"role": "user", "content": "Привет! Кто ты?"})

completion = client.chat.completions.create(
    model="local-llm",
    messages=messages,
    temperature=0.7,
    max_tokens=256,
)
messages.append(completion.choices[0].message.model_dump(exclude_none=True))

stream = client.chat.completions.create(
    model="local-llm", messages=messages, stream=True
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
```

```bash
OPENAI_API_KEY=<ваш ключ> python scripts/openai_client_example.py --no-stream --system "Отвечай одним предложением."
```

### Поддерживаемое подмножество и ограничения совместимости

Поддерживается:

- `GET /v1/models` — алиас `local-llm` и имя локальной модели;
- `POST /v1/chat/completions` — `model`, `messages` (роли `system`, `user`, `assistant`, строковый `content`), `temperature`, `max_tokens`, `stream`;
- история сообщений — сервер передаёт её Ollama целиком и по-прежнему сам её не сохраняет;
- поток: настоящая потоковая генерация Ollama преобразуется в SSE-чанки `chat.completion.chunk` и завершается `data: [DONE]`;
- ошибки — в формате OpenAI (`{"error": {"message", "type", "param", "code"}}`);
- те же rate limit, лимиты контекста, журнал и таймауты, что и у legacy `/chat`.

Не поддерживается (возвращается HTTP 400 и понятное сообщение):

- `tools`/`functions` и function calling; сообщения с ролью `tool`;
- мультимодальный `content` (массив частей, изображения, аудио);
- `response_format`, `n > 1`, `logprobs`, `seed`, `stop`, `presence_penalty`, `frequency_penalty`;
- `stream_options.include_usage`: сам объект `stream_options` принимается (клиенты присылают его автоматически), но usage-чанк в потоке не отправляется — оценённые токены не подставляются;
- роли `developer`/`tool`, а также последнее сообщение не от `user` (например, продолжение ответа ассистента);
- эмбеддинги, файлы, изображения, аудио, батчи, ассистенты — маршрутов нет (HTTP 404).

Про `usage`: поле заполняется **только** фактическими значениями `prompt_eval_count`/`eval_count`, которые вернула Ollama. Если модель их не сообщила, поле `usage` не отправляется вообще — оценки и выдуманные числа не подставляются. В потоковом режиме `usage` не отправляется (стандартный поток OpenAI его не гарантирует), в том числе при `stream_options.include_usage: true`.

Про `max_tokens`: значение клиента принимается, но ограничивается сверху серверной настройкой `MAX_OUTPUT_TOKENS`; увеличение возможно только через `.env` или панель.

Про `finish_reason`: `length` возвращается, когда Ollama остановилась по лимиту; остальные случаи приводятся к `stop`. Значения `tool_calls`, `content_filter` не выдаются, так как соответствующие возможности не реализованы.

Про параметры контекста: сообщения проходят те же проверки `/chat` — включая правило «`system` только первым». Если агент присылает несколько system-блоков в середине истории, вернётся HTTP 422 `invalid_history` — это осознанное ограничение, а не ошибка OpenAI-слоя.

## 19. Журнал запросов и приватность

По умолчанию `REQUEST_LOG_ENABLED=true`: каждый валидный запрос, дошедший до обработчика `/chat`, сохраняется как отдельный JSON-файл в `logs/requests/`. В журнал входят время, client IP, имя модели, роли и количество сообщений, оценка входных токенов, `num_ctx`, `num_predict`, время генерации, статус и **полные тексты всех сообщений и ответа модели**. Контекстные отклонения и ошибки Ollama также записываются. Не прошедшие аутентификацию, rate limit или первичную Pydantic-валидацию запросы до обработчика не доходят и в этот журнал не включаются.

Журнал намеренно хранит содержимое в открытом виде: шифрование не реализовано. Каталог `logs/` исключён в `.gitignore`; не коммитьте его, не копируйте на общедоступный диск и не отправляйте третьим лицам. Задайте `REQUEST_LOG_ENABLED=false` на странице настроек, чтобы прекратить новые записи на диск и в индекс памяти. Уже сохранённые файлы при выключении не удаляются; используйте «Удалить все логи» либо `DELETE /api/admin/logs`. Retention по умолчанию — 500 JSON-файлов; новые записи автоматически удаляют самые старые. Последние записи (до 500) восстанавливаются из файлов при старте.

`GET /api/admin/logs` показывает только метаданные; полные тексты выдаёт detail endpoint по id, защищённый `API_KEY`, если он настроен. Наличие простого локального API key — не замена шифрованию диска/HTTPS и управлению доступом ОС. Внимательно оцените правовое основание и согласие пользователей перед включением полного журналирования реальных диалогов. В демо/тестовой среде допустимо выключить запись или использовать синтетические запросы.

## 20. Настройка Rate Limit

Пример для 10 запросов за минуту на IP:

```env
RATE_LIMIT=10/minute
```

Можно настроить, например, `5/minute`, `30/hour` или `2/second`. Реализован fixed-window счётчик: для клиента учитывается число запросов за окно; при превышении вернётся `429` и заголовок `Retry-After`. Счётчик находится в памяти одного процесса, сбрасывается при его перезапуске и защищён блокировкой внутри процесса.

Ограничения:

- если запустить несколько Uvicorn worker-процессов или несколько экземпляров приложения, у каждого свой счётчик и фактический общий лимит увеличится;
- окно fixed-window допускает краткий всплеск вокруг границы двух окон;
- для нескольких процессов/узлов понадобилось бы общее хранилище счётчиков, например Redis; оно намеренно не добавлено в простой локальный проект;
- IP-лимит не является аутентификацией. Устройства за NAT могут делить адрес, а адрес клиента может меняться. Ключ защищает лишь от простого злоупотребления, не устанавливает личность пользователя.

По умолчанию доверяется адрес TCP-клиента, а произвольный `X-Forwarded-For` игнорируется. Учитывайте заголовки прокси только при `TRUST_PROXY_HEADERS=true` и только за прокси из `TRUSTED_PROXIES`.

## 21. Настройка Max Context

Настройки связаны следующим образом:

- `MAX_MESSAGE_CHARS` ограничивает каждый `content` отдельно;
- `MAX_HISTORY_MESSAGES` ограничивает размер списка сообщений;
- `MAX_CONTEXT_TOKENS` ограничивает оценку всей истории, включая `system`, роли, предшествующий диалог и новый вопрос;
- `CONTEXT_TOKEN_TOLERANCE` уменьшает оценочный бюджет на долю, оставляя запас на расхождение токенизатора;
- `MAX_OUTPUT_TOKENS` задаёт резерв генерации и `num_predict` Ollama;
- `OLLAMA_NUM_CTX` задаёт контекстное окно, запрашиваемое у Ollama; сумма максимального входа и резерва ответа должна быть не больше этого значения.

Точное число токенов зависит от модели и её токенизатора. Режим `heuristic` считает байты UTF-8 как верхнюю оценку (до одного токена на байт) плюс служебный запас на сообщение. Такой подсчёт намеренно завышает длину многих текстов и может отклонять полезные запросы раньше лимита; он не гарантирует точность для каждого специализированного токенизатора. Значение `tiktoken` использует `cl100k_base`, который также не совпадает с токенизатором Llama и остаётся оценкой. Для строгой точности подключите токенизатор, соответствующий конкретной модели.

Проверка размера тела HTTP выполняется также до Pydantic: middleware ограничивает `/chat` относительно настроенных размеров сообщений/истории (максимум 16 MiB). При превышении любого контекстного ограничения запрос отклоняется до обращения к Ollama.

При `413` сократите историю/сообщения или настройте лимиты и `OLLAMA_NUM_CTX` согласованно. Увеличение контекста может потребовать существенно больше памяти и замедлить модель.

### Фактическая проверка в текущем окружении

В среде разработки на macOS с Python 3.12.14, Ollama 0.40.0 и уже загруженной `llama3.2:3b` были получены следующие результаты:

- Автотесты: **55 passed**, один warning зависимости Starlette о deprecated alias AnyIO.
- Интеграционный запрос с историей: HTTP 200; модель ответила, что кодовое слово — «кедр» (около 0,23 с в последнем прогоне).
- Пять последовательных реальных `/chat`: **5/5 HTTP 200**, общее время 0,482 с, среднее 0,096 с.
- Пять параллельных HTTP-запросов (`concurrency=5`): **5/5 HTTP 200**, общее время 0,567 с, среднее 0,328 с.
- Большой контекст: реальный `/chat` вернул HTTP 413 и `limit_name=MAX_CONTEXT_TOKENS`; оценка запроса — 12012 UTF-8-байтов/верхних токенов, максимальный оценочный бюджет после 5% safety margin — 3891.
- Rate limit и контекст: `scripts/demo_limits.py` отправил 11 synthetic запросов после частично заполненного окна: 9 получили `413 context_too_large` (оценка 12012), 2 получили `429 rate_limit_exceeded` и `Retry-After`; генерация не запускалась.

Это результаты одной конкретной машины, прогретой модели и коротких промптов; они не являются гарантией производительности другого устройства. Скорость последовательных/параллельных запросов меняется с состоянием кэша и нагрузки.

## 24. Проверка работы с другого устройства в домашней сети

По умолчанию удалённые устройства не могут подключиться. Для временного доступа только из доверенной LAN:

1. Создайте сильный случайный API-ключ длиной не менее 32 символов, например:

   ```bash
   openssl rand -hex 32
   ```

2. В `.env` задайте `API_KEY=<сгенерированное значение>` и `HOST=0.0.0.0`. Не вставляйте ключ в историю shell-команд, общий документ или видеозапись.
3. Ограничьте входящий TCP-порт API межсетевым экраном только диапазоном/адресом домашнего устройства. Например, Linux с UFW:

   ```bash
   sudo ufw allow from 192.168.1.0/24 to any port 5012 proto tcp
   ```

   Замените диапазон на собственную домашнюю подсеть. В Windows PowerShell можно создать входящее правило только для известного адреса клиента:

   ```powershell
   New-NetFirewallRule -DisplayName 'Local LLM API LAN' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5012 -RemoteAddress 192.168.1.25 -Profile Private
   ```

   Замените `192.168.1.25` на адрес доверенного устройства и проверьте, что другое правило firewall не разрешает тот же порт шире. В macOS настройте системный firewall. Не разрешайте порт всем адресам без необходимости.
4. Запустите Uvicorn на настроенном HOST и PORT. Узнайте локальный адрес хоста (`ipconfig` в Windows; `ipconfig getifaddr en0` в macOS Wi-Fi; `hostname -I` в Linux).
5. С другого устройства в той же защищённой Wi-Fi/LAN сети отправьте запрос к `http://<LAN-IP>:5012/chat` с заголовком `Authorization: Bearer <ключ>`.
6. Убедитесь, что порт `11434` Ollama остаётся недоступен другим устройствам. Не настраивайте port forwarding на роутере и не публикуйте API в интернет.

`0.0.0.0` означает прослушивание всех интерфейсов компьютера, а не «только домашняя сеть». Доступ фактически ограничивается firewall и сетью. Не используйте такой режим в публичном Wi-Fi. Передача Bearer-ключа по обычному HTTP в LAN не шифруется; используйте только доверенную сеть. Для удалённого доступа предпочтителен защищённый VPN/туннель с контролем доступа, но в проекте он не разворачивается.

Сильный API key защищает от случайного вызова модели из LAN, но не заменяет HTTPS, firewall или пользовательскую систему аутентификации. Оставьте API на loopback, если доступ с других устройств не нужен.

## 25. Основные меры безопасности и приватности

- Безопасный default `HOST=127.0.0.1`; Ollama default `127.0.0.1:11434`.
- JSON-журнал намеренно сохраняет полное содержимое запросов/ответов по `REQUEST_LOG_ENABLED`; application logs исключений содержимого не содержат. См. раздел 19 и страницу настроек.
- Файлы подробного журнала содержат полный текст без шифрования. `logs/` исключён из Git; выключите `REQUEST_LOG_ENABLED` или удалите журнал, если сохранение не нужно.
- `.env` исключён в `.gitignore`; не коммитьте реальные API keys и секреты.
- При включённой аутентификации ключ допускается только в `Authorization: Bearer` или `X-API-Key`, сравнивается в constant time, не логируется. Не передавайте его в query string.
- Все сообщения валидируются, ограничиваются тело запроса и контекст, заданы таймауты HTTP.
- В API не передаются трассировки, локальные пути или подробности исключений Ollama.
- `X-Forwarded-For` не доверяется без явной настройки доверенного прокси.
- Ollama не открывается наружу; проект не скачивает модель во время старта.
- Нет постоянного хранилища истории, телеметрии приложения или внешних AI-интеграций.
- В коде не используется `eval`/`exec` для пользовательского текста.

Локальный запуск не гарантирует абсолютную приватность. Учитывайте безопасность и телеметрию ОС, настройки firewall и роутера, вредоносное ПО, доступ других пользователей к компьютеру, логи Ollama, браузер/CDN Swagger UI, внешние зависимости при установке и лицензионные условия модели. Для особо чувствительных данных проверьте сетевые соединения и настройки телеметрии каждого компонента самостоятельно.

## 26. Типичные ошибки и их решения

| Проблема | Что проверить |
|---|---|
| `Ollama не запущена` / `GET /health` даёт 503 | Запустите Ollama; проверьте `curl http://127.0.0.1:11434/api/tags`; сверяйте `OLLAMA_BASE_URL`. |
| Модель не установлена | `ollama list`, затем `ollama pull llama3.2:3b`; имя должно совпадать с `OLLAMA_MODEL`. |
| `model not found` | Укажите точный тег, например `llama3.2:3b`, и повторно проверьте Ollama. |
| FastAPI не стартует из-за контекста | Проверьте `MAX_CONTEXT_TOKENS + MAX_OUTPUT_TOKENS <= OLLAMA_NUM_CTX`. |
| HTTP 413 | Уменьшите текст/историю или согласованно настройте лимиты и модельное окно; увеличение окна требует памяти. |
| HTTP 422 | Убедитесь, что JSON валиден, content непустой, роли допустимы, последним идёт user, system стоит первым. |
| HTTP 429 | Подождите `Retry-After` или настройте `RATE_LIMIT`; избегайте параллельных запросов выше выбранного лимита. |
| HTTP 401 | Если задан `API_KEY`, отправляйте правильный `Authorization: Bearer ...` или `X-API-Key`. |
| HTTP 504 | Увеличьте `OLLAMA_TIMEOUT`, проверьте нагрузку и размер модели/контекста. |
| Медленная генерация/ошибка памяти | Выберите меньшую модель, уменьшите `OLLAMA_NUM_CTX`, `MAX_CONTEXT_TOKENS`, `MAX_OUTPUT_TOKENS`; убедитесь, что модель подходит железу. |
| Порт занят | Выберите свободный `PORT` и запускайте Uvicorn на нём; не останавливайте неизвестный процесс. |
| Устройство LAN не подключается | Проверьте `HOST=0.0.0.0`, firewall, IP/подсеть и маршрут; `127.0.0.1` доступен лишь локально. Ollama-порт при этом не открывайте. |
| В тестах не виден модуль `app` | Запускайте из корня проекта командой `python -m pytest`, не `pytest` из произвольной директории. |

## 27. Ограничения проекта

- Rate limit хранится в памяти одного процесса; нет общей базы счётчиков и пользовательских аккаунтов.
- Токены оцениваются приближённо и не совпадают с нативным токенизатором каждой модели.
- История не сохраняется на сервере и должна полностью приходить от клиента в каждом запросе.
- API key — простая опциональная защита; нет управления пользователями, ротации ключей, HTTPS-терминации или аудита доступа.
- API не стримит токены; ждёт завершения генерации Ollama.
- Производительность и число одновременно обслуживаемых генераций зависят от оборудования, настроек Ollama и модели.
- Только один Uvicorn worker по умолчанию. Несколько workers изменят семантику IP rate limit.
- Swagger UI по умолчанию может загружать статические assets из CDN; для полностью офлайн-режима используйте локальные assets или curl.
